## 1. Change Summary (Old vs. New Behavior)

* **Old rule (Sprint 1, Contract v1.0):** `ClinicSetting.fixedStartIntervalMinutes ∈ {5, 10, 15, 20, 30, 60}` (default `15`). Submitting `45` was correctly rejected under v1.0 with HTTP `400 VALIDATION_ERROR` by Zod, rejected by PostgreSQL constraint `chk_clinic_settings_interval`, and rejected by client inline form validation.
* **New rule (Contract v1.1):** `ClinicSetting.fixedStartIntervalMinutes ∈ {5, 10, 15, 20, 30, 45, 60}` (default remains `15`). Submitting `45` (or `"45"`) as `ADMIN` returns `200 OK`, persists to PostgreSQL, appears in `GET /api/v1/settings/public`, writes `AuditLog` (`CLINIC_SETTINGS_UPDATED`) when changed, and is selectable in `/admin/settings`.
* **Business reason:** Clinic operations require 45-minute consultation slots (follow-ups / physiotherapy) without requiring a per-clinic code hotfix.
